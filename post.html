Notes on building a design system twice.

What changed between the first pass and the one that shipped.

designcode

The first design system I built for this product was correct and nobody used it. The second one was smaller, slightly wrong in places, and it shipped. This is a note about the difference.

Tokens before components

The first time, I started with components — buttons, inputs, cards — and let the values fall out of them. The second time I started with the scale: spacing on a 4/8 grid, a type ramp with nine steps, four radii. Every component then had to explain itself in those terms, which turned out to be the whole point.

A component that needs a value the scale doesn't have is usually a component that isn't finished.

Naming is the product

Most of what people argued about wasn't the design. It was whether the thing was called surface-2 or card. I gave up on clever and named things for what they do on the page. Fewer questions, fewer wrappers.

  • Primitive → semantic → component, and nothing skips a layer.
  • One accent. Two if you can justify the second in a sentence.
  • Dark mode is a semantic block, not a second system.

What I'd keep

The audit. Once a week, a mechanical diff between the wireframes and the system — every class the pages use that the system doesn't define. The list was never empty, and it was never long.

/* three layers, nothing skips one */
--n-800: #1b1b22;          /* primitive */
--fg:    var(--n-800);     /* semantic  */
.card { color: var(--fg); } /* component */

Build it twice if you have to. Ship the second one.
